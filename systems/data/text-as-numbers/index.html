Text as numbers

Text is stored as a list of numbers, one for each character. Every character has its own code: A is 65, a is 97, a space is 32 and even the digit 7 has a code (55). Unicode gives codes to over a hundred thousand characters, including emoji.

Every message you send is stored as a list of numbers. What list is your name?

Explain it to me

Text is stored as a list of numbers, one for each character. Each character has a code: capital A is 65 and the capitals count on to Z = 90; lower case a is 97 to z = 122 (each 32 more than its capital); a space is 32; even the digit 7 is a character, code 55.

Unicode gives codes to over a hundred thousand characters, including every script and emoji. Codes up to 255 fit in one byte; bigger ones take two to four bytes.

For teachers

Students type words and read their character codes to see that text is a list of codes, one per character, including spaces, digits and lower case, and that Unicode gives codes to every character (AC9TDI8K03 node 2). About 35 minutes.

Open the teacher guide: answers, solutions, slides and a worksheet.

Students will be able to

  • I can say how a word is stored as numbers.
  • I can find the code of a letter, a space or a digit.
  • I can explain why some characters need more than one byte.

Before class

Do the Try board yourself: type a few words, then an emoji.

The one idea: text is a list of character codes, in order. The codes here are ASCII, which Unicode keeps for the first 128 characters; Unicode then gives codes to every script and to emoji. Bytes come up as "0 to 255 fits in one byte"; the binary lessons explain why.

Links: Secret messages (Code pathway) builds ciphers that shift these codes; this lesson is the theory those lessons assume.

Running the lesson

  1. Predict: students who chose 3, 1, 2 used alphabet positions; ask what A's code is.
  2. Try: have everyone type their first name and compare: whose code list is longest?
  3. Worked example: before the 7 line, ask what the digit's code will be.
  4. Vary: ask why the emoji's code is so big.
  5. Make: ask what rule they used to turn capitals into lower case.

The hard part (on purpose)

Students treat a digit in text as an amount (7 stored as 7). Have them type 7 on the board and read the code aloud before the Worked example.

When students get stuck

  • A student writes 7 for the digit 7 (Sam's mistake). Ask: What does the board show when you type 7? Fix: In text a digit is a character: 0 is 48, so 7 is 55.
  • A student forgets the space. Ask: How many characters are in hi there, counting the gap? Fix: The space is a character too: 32.
  • A student can't find a lower case code. Ask: What is the capital's code? Fix: Add 32.

Stretch and support

Stretch: Look up the Unicode code for an emoji you like (or type it on the board). Why do emoji make text messages bigger?

Support: Give the code table: A = 65 … Z = 90, a = 97 … z = 122, 0 = 48 … 9 = 57, space = 32.

What each step is for

  • how is CAB stored?: Committing to how a word is stored shows whether students expect one code per character (and A = 65 counting on), alphabet positions, or the letters themselves stored.
  • Try: type a word: Typing CAB and reading the codes settles the prediction: one code per character, in order.
  • Worked example: Hi 7!: Encoding Hi 7! one character at a time models the new move, including the cases students forget: lower case has its own codes, a space is a character, and a digit is a character with a code. Sam stores the digit 7 as 7, the misconception planted after the method.
  • Vary: change one character: Each task changes one thing in the typed text: case, one letter, a digit, a space, then a character beyond one byte (Unicode).
  • codes: Codes both ways, a digit and a space, case in passwords, and a review that the same numbers read as another kind of data mean something else.
  • change case with numbers: Changing the codes to turn HI into hi, without typing, reverses the process: students use the rule (lower case is 32 more) to set the numbers directly.

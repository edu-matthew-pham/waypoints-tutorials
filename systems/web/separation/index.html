Why keep them apart

Keeping content, structure and presentation apart lets each change on its own: one style sheet restyles a whole site, the same page fits a phone or a laptop, and a screen reader can tell a blind reader what each part is. A page that fakes its structure with looks works for nobody but sighted readers.

Two pages look almost the same. To a blind student using a screen reader, one of them has no headings at all. How?

Explain it to me

Keeping the layers apart means each one can change on its own:

  • A whole site: one style sheet styles every page, so one change restyles them all.
  • Phones: the same content and structure get different presentation on a small screen.
  • Screen readers: they read the structure aloud (headings, lists, menus), so a heading faked with big bold text is just plain text to a blind reader.

Structure says what each part is; presentation only says how it looks.

For teachers

Students hear two look-alike pages through a screen reader, restyle a three-page site with one CSS rule, view a page at phone width, and fix a page whose structure was faked with looks (AC9TDI10K02 node 3), with no coding needed beyond tidying tags. About 45 minutes.

Before class

Try the boards yourself.

The one idea: separation lets each layer change on its own, which is what makes sites maintainable, adaptable and accessible. The accessibility point matters most to many students; a short screen reader demo (VoiceOver on a Mac or iPad, Narrator on Windows) on a real page lands it.

The board's screen reader is a simplified model: it announces headings, links, lists and landmarks, as real screen readers do, but real ones say much more.

Page B (the "messy" page) uses tags that are still found on old sites (font, b, br for layout); they work but carry no meaning.

Running the lesson

  1. Predict: students who chose "Heading level 2" for Page B think the reader sees the look.
  2. Try: ask a student to describe how they would find "Coming up" on Page B without seeing it.
  3. Worked example: ask who else reads structure: search engines, translation tools, reader view.
  4. Vary: after one rule restyles three pages, ask how that would go with 200 pages styled by hand.
  5. Make: listen to the fixed page together in the screen reader.

The hard part (on purpose)

The Make asks students to edit HTML for the first time in this course. It is hard on purpose but small: the screen reader shows what's missing; let them use it rather than giving the tags.

When students get stuck

  • A student says the two pages are the same (Sam's mistake). Ask: Turn on the screen reader for both. What does each say first? Fix: Same look, different structure: not the same page for everyone.
  • A student's fixed page still shows tags used only for looks. Ask: Which tags are left? Which part should each be? Fix: Replace b and font with h1 or h2; turn the br lines into li items in a ul.

Stretch and support

Stretch: Look up the Web Content Accessibility Guidelines (WCAG). Find one rule that is about structure and one about presentation.

Support: A list of the structure tags they need for the Make: h1, h2, p, ul, li, nav.

What each step is for

  • what the screen reader says: Committing to what a screen reader announces tests the new move: tools read the structure, not the look.
  • Try: listen to both pages: Hearing both pages through the screen reader settles the prediction: same look, different structure, different experience.
  • Worked example: three reasons: Working through three situations models the new move: each benefit comes from one layer changing while the others stay. Sam judges a page by its look, the misconception planted after the method.
  • Vary: one change, many effects: Each task changes one thing and watches what follows: one CSS rule across a site, the screen width, then the style sheet off with the screen reader on.
  • why it matters: Explaining separation in new situations is the same move in mixed forms, plus a review of the three layers.
  • fix Page B: Repairing a page whose structure was faked with looks reverses the process: from what each part should be to the tags that say so.

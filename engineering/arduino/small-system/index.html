A small system

A system reads a sensor, decides, and drives an output, and a brief says what it must do. Test it against a table of cases: each side of every threshold, the threshold itself, and the extremes. Tests that pass far from the threshold can hide a mistake right at it.

Your plant-water alarm works on your desk: it blinks when you twist the knob down. Does it meet the brief? How would you know, without watching it for a week?

The brief: a plant-water alarm. A soil moisture sensor on A0 reads low when the soil is dry (the knob stands in for it). The LED on pin 13 must blink when the reading is 300 or below, and be off otherwise.

A test case sets the sensor to one reading and says what the LED should do. Run the tests runs the sketch once for each case and ticks or crosses it.

How this lesson works: Predict, Try, Investigate, Modify, Practise, Make
  • Predict: Read the problem and decide what you think before you try anything. A wrong guess is fine: it shows you what to look for.
  • Try: Try it on the board and compare the result with your prediction.
  • Investigate: Work out why it happens, one step at a time.
  • Modify: Change the problem on purpose and see what happens.
  • Practise: A few on your own, to check you have it.
  • Make: Make your own problem using what you have learned. Expect a few tries; that is normal.

For teachers

Students run a plant-water alarm against a test table that passes but misses the threshold, learn to choose test cases (either side of the threshold, the threshold itself, the ends), fix an off-by-one, add a steady state, build it on real hardware, and meet a three-band fridge alarm brief against six tests. About 50 minutes.

Open the teacher guide: answers, solutions, slides and a worksheet.

Students will be able to

  • I can choose test cases for a brief, including the boundary.
  • I can fix a sketch until every test passes.
  • I can explain what passing tests does and doesn't show.

Before class

The board's Run the tests runs the sketch once per case with no waiting (3 s of board time each) and records what the first LED did: off (never on), on (came on once and stayed on) or blink (came on two or more times).

This lesson is the Years 9–10 test-case idea (AC9TDI10P06, validate against test cases) met in Years 8–9 hardware; Code's console bridge has the same table-of-inputs idea in Python.

Running the lesson

  1. Try: ask whether 5 out of 5 means the alarm meets the brief.
  2. Worked example: write the table live from the brief.
  3. Vary, three states: ask which case to test first in the if, and why.

The hard part (on purpose)

Students treat 'it worked when I tried it' as done. Ask which reading they tried, and which reading the brief is about.

When students get stuck

  • A student's steady-on case fails as blink. Ask: Does your steady branch switch the LED off anywhere? Fix: Steady on: HIGH only, no LOW in that branch.
  • A student changes the tests' expectations in their head. Ask: What does the brief say for 300? Fix: The brief decides, not the sketch.

Stretch and support

Stretch: Stop the flicker near the threshold: switch on at 300 or below, and only switch off again above 320.

Support: A blank test table with columns reading, should do, did, ✓/✗.

What each step is for

  • which test finds it?: Committing to which reading exposes an off-by-one at the threshold tests the new move: the boundary is where the slips are.
  • Try: run the tests: Every test in this table passes, yet the sketch misses the brief: the table has no case at the threshold. That sets up the method.
  • Worked example: choose the tests: Building a test table from the brief models the move: one case each side of the threshold, the threshold itself, and the extremes. Sam's two far-away tests are planted after the method.
  • Vary: change the brief: Each task changes the brief and its tests; students change the sketch until every case passes, including a new steady state.
  • Build it for real: On real hardware the readings aren't neat: printing them and testing at the edges shows how a real sensor behaves.
  • tests: Choosing test cases for new briefs, including an inclusive and an exclusive threshold.
  • a fridge door alarm: Meeting a three-state brief against a full test table brings the unit together: read, decide in bands, act, test.

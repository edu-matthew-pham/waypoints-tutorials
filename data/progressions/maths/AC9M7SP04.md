# AC9M7SP04 — Algorithms for classifying shapes

**Year 7**
**Strand:** Space

## ACARA Descriptor

design and create algorithms involving a sequence of steps and decisions that will sort and classify sets of shapes according to their attributes, and describe how the algorithms work

## Prior Knowledge

Students can classify triangles, quadrilaterals and polygons by properties (from AC9M7SP02). Students have experience writing step-by-step instructions and using decision trees informally.

## Progression Endpoint

Students design and describe algorithms (using flowcharts or pseudocode) that sort and classify shapes by their attributes.

## Waypoint Sequence (2 waypoints, 1 hinge)

#### 1. Designing a classification algorithm ⚑ ★

Students design a step-by-step algorithm (as a flowchart or decision tree) that classifies shapes according to their attributes.

**⚑ Hinge:** Students who design algorithms without an explicit decision-ordering scaffold produce algorithms with missing branches or ambiguous tests — these cannot be evaluated or described correctly in Node 2, since tracing an incomplete algorithm produces unpredictable outputs.

**Response modes:**
- ◎ Scaffold reasoning: Algorithm design requires explicit thinking about the order of decisions and what each branch tests. Students who write algorithms informally miss cases and produce ambiguous decision points.

**Minimum width:** Create a flowchart that correctly classifies triangles as scalene, isosceles or equilateral.

**Typical width:** Design and test an algorithm for classifying quadrilaterals; identify and fix errors when the algorithm misclassifies a shape.

**Wider:**
- Design an algorithm for a broader polygon classification including regularity and convexity.
- Compare two algorithms for the same classification task — which is more efficient? Which handles edge cases better?

**Success criteria:**
- Produces a flowchart or decision tree that correctly classifies the target shapes.
- Includes decision points with clear yes/no branches.
- Tests the algorithm on at least two examples and corrects any errors.

**Related standards:**
- AC9M7SP02

#### 2. Describing and evaluating algorithms

Students describe in words how an algorithm works and evaluate its correctness by tracing through it with test cases.

**Response modes:**
- ↔ Widen contexts: Algorithm evaluation requires seeing both correct and incorrect algorithms to develop critical judgment. Students who only design algorithms rarely develop the ability to critique others'.

**Minimum width:** Trace a given classification algorithm with two test shapes and describe each decision made.

**Typical width:** Evaluate whether a given algorithm is correct, efficient, and handles all cases; identify and fix errors.

**Wider:**
- Implement the classification algorithm in a simple programming language or flowchart tool.
- Investigate the relationship between the number of decision steps and the number of categories — how does complexity scale?

**Success criteria:**
- Correctly traces a classification algorithm with a test input.
- Identifies at least one case where a given algorithm fails (if one exists).
- Explains in plain language how the algorithm works.

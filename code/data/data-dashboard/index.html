A data dashboard

Read the table with pandas and put it behind a Gradio app: choose a genre, see its songs as a table and a bar chart.

Dashboards are how organisations look at their data every day: choose something, and the tables and charts update.

You have done it all by hand: reading rows, filtering, counting, charting. Now meet the tools data scientists use for the same jobs. pandas reads a CSV into a table in one line (and numbers stay numbers), and Gradio turns a function into an app with inputs and outputs.

The playground runs a small stand-in for Gradio, so it works in the browser. The same program runs unchanged in real Gradio on a computer or a Hugging Face Space.

  • Predict: Read the code and say what it will do before you run anything. A wrong guess is fine: it shows you what to look for.
  • Run: Run it and compare the result with your prediction.
  • Investigate: Trace how each line of code connects to what you see.
  • Modify: Change the code on purpose and check the result.
  • Make: Build something new using what you have learned. Expect a few tries; that is normal.

dashboard.py
import gradio as gr
import pandas as pd

songs = pd.read_csv("music.csv")


def by_genre(genre):
    rows = songs[songs["genre"] == genre]
    return rows, rows


genres = sorted(songs["genre"].unique())
gr.Interface(
    fn=by_genre,
    inputs=gr.Dropdown(genres, label="Genre"),
    outputs=[gr.Dataframe(label="Songs"), gr.BarPlot(x="title", y="minutes", label="Length in minutes")],
    title="Music detective",
).launch()

        Where this leads

        On a computer, pip install gradio pandas runs this same file as a real web app, and your teacher can host it as a Hugging Face Space for the class. The same table and the same pandas lead to machine learning: training a model to predict a column from the others.

        Your dashboard reads music.csv. What would it take to use it for your class's own survey?

        For teachers

        Students read the music data with pandas, filter it in one line, and put it behind a Gradio dashboard with a dropdown, a table and a bar chart, then add a year slider, sort the rows and build a dashboard of their own. About 50 minutes.

        Open the teacher guide: answers, solutions, slides and a worksheet.

        Students will be able to

        • I can read a CSV with pandas and filter its rows with a test.
        • I can make a Gradio app from a function, its inputs and its outputs.
        • I can add an input by adding a component and a matching parameter.

        Before class

        Read the unit primer first. The playground runs a small stand-in for Gradio (Textbox, Number, Slider, Dropdown, Checkbox, Dataframe, BarPlot with gr.Interface), written so the same file runs unchanged in real Gradio; on a computer, pip install gradio pandas and python app.py runs it as a real web app, and a teacher can host it as a Hugging Face Space (Hugging Face accounts need age 13+). pandas takes a few seconds to load the first time. pd.read_csv reads the file into a table (a DataFrame) and keeps numbers as numbers. songs[songs["genre"] == genre] keeps the rows where the test is true: Lesson 1's loop and if in one line. Gradio calls the function with one argument per input, in order, and puts each returned value in an output, in order. import gradio as gr and the gr. / pd. forms are recipes here.

        Running the lesson

        1. Predict: draw the app on the board: a dropdown, a button, an output box, and an arrow through the function.
        2. Run: ask students which line of Lesson 1 the filter line replaces.
        3. Modify: add the slider to inputs and the parameter to the function at the same time; count both.
        4. Make: have students write their question in a comment before any code.

        The hard part (on purpose)

        Lining up inputs, parameters and outputs when adding the slider. Ask students to count each list aloud before running.

        When students get stuck

        • TypeError: by_genre() takes 1 positional argument but 2 were given. Ask: How many inputs are there, and how many parameters does the function have? Fix: Add a parameter for every input, in the same order.
        • The table shows but the chart is empty or wrong. Ask: Do x and y name columns that are in the table? Fix: x="title", y="minutes": column names exactly as in the file.
        • KeyError: 'Genre'. Ask: How is the column named in the file? Fix: Column names must match exactly, including capitals.

        Stretch and support

        Stretch: Add a Checkbox "Australian artists only" with a list of artist names and isin(...), or a second chart of counts per year.

        Support: Give students the Slider line written out, and ask them only to add the parameter and the filter line.

        Where it leads

        Machine learning with Gradio (coming later) trains small models on the same tables. Web apps with Flask builds the pages behind an app by hand.

        What each step is for

        • Investigate: pandas filters a whole table in one line, keeping the rows where a test is true; Gradio calls the function with the inputs and shows each returned value in an output.
        • Modify: Each new input is one more component in inputs and one more parameter of the function, in the same order.
        • your own dashboard: Goals only: a question of your own, answered by a function, with inputs and outputs Gradio can show.

        • Make a Gradio app from a function, its inputs and its outputs.
        • Add an input by adding a component and a matching parameter.

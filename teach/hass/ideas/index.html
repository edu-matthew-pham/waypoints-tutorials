Part 1 shows which is which, what each idea looks like in each tool, and where each pathway first teaches it. Part 2 adds the few ideas each pathway has of its own.

Why these ideas matter, even if coding isn't your strength

You don't need to be a programmer to teach or use these ideas. They are about what a program does, not the exact words you type: the same idea looks different in blocks, Python and JavaScript, and the plain words below are enough to talk about it.

The ideas also matter when an AI tool helps write some of the code, as it increasingly does. Someone still has to say precisely what the program should do, check that it does it, and say what to change when it doesn't. That takes the ideas on this page, the hinge ideas most of all: a value that changes as the program runs, the loop counter, and the yes-or-no questions, where mistakes hide at the edges (does “more than 10” include 10?). Typing the code by hand may matter less than it did; knowing what each part does, and predicting what it will do, matters as much as ever.

Part 2: what each pathway adds

Each pathway also has a few ideas of its own. These are often what a teacher new to that tool finds hardest, because they are about the tool's world (pages, devices, games, text programs) rather than coding in general. Each says which shared ideas it builds on.

Web

Making pages: what each part is, how it looks, and how code can change it.

IdeaLooks likeFirst taught in
What it is, and how it looks

HTML says what each part of a page is (a heading, a list, a link). CSS says how it looks. You can change the whole look without touching the content.

Builds on: Steps in order

<h1>My club</h1>

h1 { color: teal; }

Rules and selectors · Structure and style a page

Boxes inside boxes

Every part of a page is a box, and boxes sit inside other boxes, like folders inside folders. Laying out a page means arranging those boxes.

Builds on: What it is, and how it looks

<section>
  <h2>News</h2>
  <p>…</p>
</section>

Tags inside tags · Structure and style a page

One page, every screen

The same page rearranges its boxes to fit a phone or a big screen, instead of making a page for each.

Builds on: Boxes inside boxes

.cards { display: flex;
         flex-wrap: wrap; }

Fit any width · Layout and components

Code can change the page

JavaScript can find a part of the page and change it after the page has loaded, for example when someone clicks a button.

Builds on: Boxes inside boxes, Events

document.querySelector("h1")
  .textContent = "Welcome back!";

When two sprites touch

When two sprites overlap, an event runs: a coin is collected, a life is lost. The kind of each sprite decides which event.

Builds on: Sprites, Events

change score by 1

Every frame

Many times a second the game moves everything a little, checks what has happened and redraws the screen. Code can run on every one of those frames.

Text that looks like a number hinge

Whatever someone types arrives as text, even "12". It has to be turned into a number before you can do sums with it.

Students are often surprised that "12" + "1" gives "121".

Builds on: Asking the user, Variables

age = int(input("Age? "))
print(age + 1)

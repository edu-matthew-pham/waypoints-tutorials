← AC9TDI10K01 Managing and securing networked systems

Cryptographic security mechanisms

AC9TDI10K01 n4 · waypoint 4 of 5 · Year 10 Digital Technologies (knowledge) · Networks and security · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (knowledge): treat it as a starting suggestion and check it before use.

Checkpoint

Students can explain how public key cryptography and hashing are used to secure the transmission and storage of data in networked systems.

Lessons on this site

  • Hashes and salt
  • Public and private keys

Success criteria

  • Correctly explains what public key cryptography protects (data in transit) and how it does so
  • Correctly explains what hashing protects (stored data / integrity verification) and how it differs from encryption

Prior knowledge

Waypoint 3: Access control mechanisms.

Width

Minimum
Explain, in plain language, how one cryptographic mechanism (e.g. TLS for transmission OR hashing for storage) protects data.
Typical
Explain how public key cryptography (e.g. TLS) secures data in transit and how hashing (e.g. SHA-1) protects stored data; describe the different threat each addresses.
Wider
  • Investigate how certificate authorities establish trust in public key cryptography — what happens when a certificate is invalid or expired?
  • Explore how modern systems combine symmetric and asymmetric encryption to gain the security benefits of asymmetric without the performance cost
  • Research how First Nations community health data is protected using encryption standards in remote health systems — why data sovereignty requirements shape cryptographic choices

Hinge

Conflating encryption with hashing, or treating all cryptography as identical, breaks the N5 integration — students cannot correctly identify which mechanism protects data in transit versus at rest.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepCryptography is conceptually dense — students often conflate encryption with hashing, or assume all encryption is the same. Multiple concrete examples (HTTPS padlock, password storage, certificate chain) each illuminate a different aspect and build the distinction through contrast.

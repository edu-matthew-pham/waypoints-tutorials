Refining and evaluating the algorithm

AC9M9SP03 n3 · waypoint 3 of 3 · Year 9 Maths · Space

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Maths: treat it as a starting suggestion and check it before use.

Checkpoint

Students can refine an algorithm based on test results and evaluate the refinement, explaining what changed and why it improves the algorithm.

Lessons on this site

  • Refine it and explain the change

Success criteria

  • Makes a specific, justified refinement to the algorithm based on a test failure
  • Retests with the previously failing case and confirms the refinement resolves it
  • Evaluates the refined algorithm: states what it now handles correctly and any remaining limitations

Prior knowledge

Waypoint 2: Testing an algorithm with cases.

Width

Minimum
Make one refinement to an algorithm based on a failure case identified during testing; explain what the refinement changes and why; retest with the previously failing case.
Typical
Refine an algorithm to handle failure cases, improve efficiency or increase generality; retest after refinement; discuss and evaluate the refinement — explain what the algorithm now does that it did not before, and any remaining limitations.
Wider
  • Develop an algorithm for animating a geometric construction (e.g. step-by-step angle bisection or perpendicular bisector) and evaluate it using multiple test cases, refining until it handles all valid inputs correctly
  • Investigate how software developers approach algorithm refinement — discuss the concept of debugging as a structured process of identify-fix-retest
  • Evaluate two different algorithms for the same geometric task and compare their efficiency, correctness and generality

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Integration: a combining task at the wider tierRefinement and evaluation integrate design, testing and geometric reasoning into the full algorithm development cycle. The integration challenge is connecting the geometric insight (why this theorem or construction works) to the algorithmic fix (how to handle the edge case in code/pseudocode). This is the descriptor's full demand.

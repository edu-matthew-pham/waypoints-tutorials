← AC9M10SP03 Algorithms for spatial problems

Testing, refining and justifying

AC9M10SP03 n3 · waypoint 3 of 3 · Year 10 Maths · Space

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Maths: treat it as a starting suggestion and check it before use.

Checkpoint

Students can test an algorithm against multiple cases, identify and fix failures, and communicate why the refined solution addresses the problem.

Success criteria

  • Student tests the algorithm against at least two cases and correctly identifies a failure case
  • Student describes a specific refinement and explains how it addresses the identified failure
  • Student communicates the solution and justification clearly to a specified audience

Prior knowledge

Waypoint 2: Designing algorithms for spatial problems.

Width

Minimum
Test an algorithm against at least two different input cases; identify one case where it fails or produces unexpected output; describe a refinement to address the failure.
Typical
Test algorithms against a range of cases including edge cases; systematically identify failure modes; refine the algorithm to address failures; validate the refined version; communicate the solution and justification in clear terms appropriate for the audience.
Wider
  • Investigate how geospatial technologies used by First Nations Australians' communities address spatial problems of position and transformation — considering how these established methods relate to computational verification
  • Apply the testing process to a self-similar pattern algorithm — validate against multiple iteration depths and compare the algorithmic output to a geometric description of the pattern

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepTesting and refinement takes very different forms across problem types — testing a floor plan algorithm requires spatial visualisation, testing a network routing algorithm requires tracing paths, testing a fractal algorithm requires iteration tracing. Multiple problem types build the generalised testing mindset.
Integration: a combining task at the wider tierTesting and justification integrates problem decomposition (node 1), algorithm design (node 2) and communication into the complete design cycle. It is the node where algorithmic thinking becomes a full engineering practice.

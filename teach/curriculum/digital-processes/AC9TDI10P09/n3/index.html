Reading and modifying modular programs

AC9TDI10P09 n3 · waypoint 3 of 5 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can read and interpret programs split across multiple functions, files or classes, and modify them to add functionality.

Lessons on this site

No lesson is tagged to this waypoint. The standard is generally covered by some courses; see the standard's page for which are the main focus and which only touch it.

Success criteria

  • Correctly identifies what at least two modules/functions/classes do in a provided codebase
  • Makes a modification that works correctly without breaking existing functionality

Prior knowledge

Waypoint 2: Defining custom classes.

Width

Minimum
Read a provided modular program (split across files or functions); identify what each module does; make one modification that adds or changes functionality.
Typical
Read a program split across files, functions and/or classes; trace execution flow across modules; make modifications that add new functionality without breaking existing behaviour; explain how the modular structure made the modification easier.
Wider
  • Extend a provided game codebase (e.g. an adventure game) by adding new characters, levels or abilities — identify where in the existing structure each addition belongs
  • Investigate how large codebases manage module dependencies and explain what problems arise when modules are tightly coupled

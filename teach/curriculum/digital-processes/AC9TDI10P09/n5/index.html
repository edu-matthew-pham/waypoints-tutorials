Implementing a complete modular program

AC9TDI10P09 n5 · waypoint 5 of 5 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write and edit a modular program that receives structured input, applies algorithms and data structures, and produces correct output.

Lessons on this site

No lesson is tagged to this waypoint. The standard is generally covered by some courses; see the standard's page for which are the main focus and which only touch it.

Success criteria

  • Program is split into at least two logical modules (functions or classes)
  • Program produces correct output for at least two different test inputs
  • Program handles at least one edge case without crashing

Prior knowledge

Waypoint 4: Debugging programs.

Width

Minimum
Write a program that uses at least one custom class or function and processes structured input to produce output; the program produces correct output for a test input.
Typical
Implement a program that is split into logical modules (functions and/or classes); the program processes structured input, applies appropriate data structures and algorithms, and produces correct output for the problem; test with multiple inputs.
Wider
  • Write a program that reads structured data from a file (e.g. timestamped sensor data) and processes it to produce an output — such as a graph of an altitude sensor's flight path
  • Build a program that models a real inventory, library or tracking system using custom classes — implement the required methods to track state changes over time
  • Use a data structure from a library (e.g. binary search function) in a program and explain why using the library is preferable to reimplementing from scratch

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Integration: a combining task at the wider tierNodes 1–4 cover data structures, classes, reading modular code, and debugging separately. Implementation requires all of these simultaneously — choosing data structures, defining classes, organising modules, and debugging when things go wrong. Students who can do each individually often struggle when they must design the whole program architecture.

Collaborative version control

AC9TDI10P12 n2 · waypoint 2 of 4 · Years 9–10 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can use a collaborative version control tool to manage shared code development, tracking changes and coordinating contributions.

Lessons on this site

None yet.

Success criteria

  • At least two commits are made with meaningful commit messages
  • Contribution history shows individual contributions are trackable

Prior knowledge

Waypoint 1: Planning with agile decomposition.

Width

Minimum
Make at least two contributions to a shared repository; explain what each contribution changed and why version control is useful.
Typical
Use a collaborative version control tool (e.g. GitHub) to plan, decompose and manage contributions with peers; commit changes with meaningful messages; explain how version control prevents conflicting changes and maintains a history of work.
Wider
  • Deliberately create a merge conflict and resolve it — explain what caused the conflict and how the resolution was reached
  • Use branching to develop a new feature independently of the main codebase and merge it when complete — explain what branches enable in team development

Hinge

Version control workflow fluency is prerequisite for collaborative project execution — students who cannot commit, push and pull correctly lose each other's work and cannot demonstrate the collaborative project management the descriptor requires.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Consolidation: more practise steps, short feedback loopsVersion control workflows require precise procedural knowledge — staging, committing, pushing, pulling, resolving conflicts. Students need sufficient practice with the workflow before they can use it fluently in a collaborative context. Errors in this workflow cause lost work and confusion.

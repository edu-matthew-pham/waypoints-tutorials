Data flow diagrams for threat modelling

AC9TDI10P13 n1 · waypoint 1 of 3 · Years 9–10 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can use a data flow diagram to trace how private information moves through a system and identify where it is most at risk.

  • Threat models

Success criteria

  • Data flow diagram correctly shows at least two data flows between system components
  • At least one threat is identified at a specific point in the diagram with an explanation of why that point is at risk

Prior knowledge

Students can explain how multi-factor authentication protects accounts and manage basic security settings (AC9TDI8P13). They understand access control concepts from AC9TDI10K01. They have not yet modelled how data moves through a system, constructed a threat model, or explored how specific vulnerabilities can be exploited.

Width

Minimum
Draw a data flow diagram for a simple system showing at least two data flows; identify one point where the data could be at risk.
Typical
Map how data moves between user, application and server in a web-based system using a data flow diagram; identify points where data is transmitted, stored, or processed; for each point, identify what threat exists and why that point is a target.
Wider
  • Map data flows in a more complex system with multiple actors (user, server, third-party APIs) and identify threats at each boundary
  • Compare the data flow diagram for the same system with and without a specific security control — explain how the control changes the threat profile

Hinge

Data flow diagrams are the analytical foundation for N2 and N3 — students who cannot map how data moves through a system cannot identify where it is at risk (N2) or trace the steps of exploiting a vulnerability (N3).

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Structured reasoning: a worked chain of reasons, then a write-and-compare (reasoning) checkThreat modelling requires systematic thinking — for every data flow, what is the threat? Students who approach security intuitively spot obvious threats (password interception) but miss subtler ones (session token exposure, plaintext in logs). The data flow diagram provides the structure that makes systematic threat identification possible.

Writing and running a sequential program

AC9TDI4P04 n1 · waypoint 1 of 4 · Years 3–4 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write a program that executes steps in order and run it to check it performs as expected

Lessons on this site

None yet.

Success criteria

  • Program runs without errors
  • Steps execute in the correct order

Prior knowledge

Students can follow and describe algorithms involving sequencing, branching and iteration (AC9TDI4P02). They have described these structures but have not yet implemented them in a programming environment. They have not yet written programs that accept user input.

Width

Minimum
Write a program with at least three sequential steps, run it, and confirm it performs each step in the correct order
Typical
Write and run sequential programs across simple tasks (moving a character, displaying messages, performing calculations); identify what step the program is on when paused
Wider
  • Implement a sequential program that enacts a specific ordered procedure — for example, the strict steps a First Nations ranger follows when handling a specific native animal; discuss why the order must be preserved in the program
  • Write the same sequential program in two different visual environments (e.g. Scratch and a flowchart tool) and compare how each represents the same logic

Hinge

Students who cannot reliably sequence blocks and run programs cannot add branching or iteration — both require a functioning sequential program as the base. Fluency here is directly prerequisite for N2 and N3.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Consolidation: more practise steps, short feedback loopsWriting and running sequential programs is the foundational capability for all subsequent programming work in this descriptor. Students need procedural fluency — the ability to reliably sequence blocks and interpret run output — before branching and input are introduced. Practice and precision here matter more than breadth.

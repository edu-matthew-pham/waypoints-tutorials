Adding iteration to programs

AC9TDI4P04 n3 · waypoint 3 of 4 · Years 3–4 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write a program that repeats steps a fixed number of times and explain what changes with each repetition

Success criteria

  • Loop executes the correct number of times
  • Program produces the expected output after the loop completes

Prior knowledge

Waypoint 2: Adding branching to programs.

Width

Minimum
Write a program that repeats a step a set number of times (e.g. displaying repeated song lyrics, computing a sum using repeated addition); confirm it repeats the correct number of times
Typical
Write programs using fixed-count loops for different purposes (repeated display, repeated addition, repeated movement); identify what changes across repetitions and what stays constant
Wider
  • Write a program that uses a loop to process multiple inputs (e.g. asking for a user's name and responding to each) — discuss how loops reduce the need to repeat code manually
  • Implement a program that uses both a loop and a branch — for example, a loop that counts and branches when a condition is reached; discuss how the structures combine

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepStudents who only see loops in one context (e.g. printing repeated text) may not recognise that the same structure applies to movement, calculation and input processing. Multiple task contexts build generalised understanding of iteration as a structure.

← AC9TDI4P01 Define problems with user stories

Defining a problem using both tools

AC9TDI4P01 n3 · waypoint 3 of 3 · Years 3–4 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can use design criteria and a user story together to define a problem — stating what the solution must do and who it is for

Lessons on this site

None yet.

Success criteria

  • Writes a user story with a named user, need and purpose
  • States at least two design criteria consistent with the user story

Prior knowledge

Waypoint 2: User story structure.

Width

Minimum
Given a problem context, co-create a user story and identify two design criteria the solution must meet
Typical
Define problems across different contexts using user stories and design criteria together; check that the criteria are consistent with the needs identified in the user story
Wider
  • Define a problem involving data collection for a community need (e.g. monitoring local wildlife populations) — write user stories from multiple user perspectives and derive design criteria that satisfy all of them
  • Explore a problem from a First Nations context (e.g. using digital tools to document cultural knowledge) — discuss how the user story and criteria might differ from a mainstream educational tool

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Integration: a combining task at the wider tierThis node asks students to hold design criteria and user stories in relation — checking that criteria actually capture what the user needs. The integration step (do the criteria follow from the user story?) is a reasoning move that needs explicit practice.

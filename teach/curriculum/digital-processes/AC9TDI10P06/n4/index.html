← AC9TDI10P06 Validate algorithms and programs

Systematic validation against a test suite

AC9TDI10P06 n4 · waypoint 4 of 4 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can design and apply a complete test suite that validates an algorithm or program against normal inputs, boundary cases and invalid inputs.

Success criteria

  • Test suite includes at least one normal, one boundary and one invalid input test case
  • Expected output is defined for each test case before testing
  • Outcome (pass/fail) is recorded for each test case

Prior knowledge

Waypoint 3: Testing with invalid inputs and error handling.

Width

Minimum
Design a test suite with at least three test cases (normal, boundary, invalid); apply each to the algorithm or program and record the outcome.
Typical
Design a complete test suite; apply each test case; record expected vs actual output; for any failed test, trace the algorithm to locate the error and fix it; re-run the test suite to confirm the fix.
Wider
  • Apply the test-fix-retest cycle to a program with multiple bugs, tracking which bugs are introduced or unintentionally fixed by each change
  • Compare manual test suites with automated testing approaches — explain what automation enables that manual testing cannot scale to
  • Design a test suite for an algorithm at a peer's solution and explain each test case's purpose to the peer

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Integration: a combining task at the wider tierA complete test suite integrates tracing (node 1), boundary identification (node 2) and invalid input testing (node 3) into a coordinated validation approach. Students who can do each step individually often produce incomplete test suites by defaulting to only normal-case tests. Integration here is recognising what categories of testing are needed and deliberately including all three.

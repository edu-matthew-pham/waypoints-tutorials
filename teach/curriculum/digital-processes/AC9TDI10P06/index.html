Validate algorithms and programs

AC9TDI10P06 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Descriptor

validate algorithms and programs by comparing their output against a range of test cases

Prior knowledge

Students can trace algorithms to predict output for a given input and identify errors (AC9TDI8P06). They can identify when a program's state is unexpected. They have not yet designed systematic test suites including boundary and invalid input cases, or applied a validation methodology beyond ad-hoc tracing.

By the end

Students validate algorithms and programs by designing and applying a range of test cases — including boundary cases and invalid inputs — to confirm correct behaviour or identify errors.

ACARA elaborations

Examples from ACARA that illustrate this standard. They are examples, not a checklist, and belong to the standard as a whole.

  • tracing and debugging an algorithm by identifying when its state is unexpected, why this has occurred, and the changes needed to correct it, for example identifying that a loop has finished one iteration too early
  • determining boundary test cases and testing that they are handled correctly by a program, for example checking that an intersection is detected when 2 shapes are perfectly aligned
  • generating invalid input and user errors and testing that they are handled appropriately by a program, for example checking that a program does not crash when text is entered instead of a number

This is general coverage, not a lesson tagged to each waypoint. A course that only touches a standard meets it in passing; it may not be the course's main focus, and a teacher could extend it to cover the standard more fully.

Waypoints

  • 1. Tracing algorithms and identifying unexpected stateHingeStudents can trace an algorithm to identify when its state becomes unexpected, why this occurred, and what change is needed.
  • 2. Designing boundary test casesHingeStudents can identify boundary conditions for an algorithm or program and design test cases that verify boundary behaviour is handled correctly.
  • 3. Testing with invalid inputs and error handlingStudents can generate invalid inputs and user errors and verify that programs handle them appropriately without crashing.
  • 4. Systematic validation against a test suiteStudents can design and apply a complete test suite that validates an algorithm or program against normal inputs, boundary cases and invalid inputs.

Testing with invalid inputs and error handling

AC9TDI10P06 n3 · waypoint 3 of 4 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can generate invalid inputs and user errors and verify that programs handle them appropriately without crashing.

Success criteria

  • Tests at least one invalid input type
  • Identifies whether the program's response to invalid input is appropriate (handled gracefully) or a failure (crashes, silent corruption, wrong output)

Prior knowledge

Waypoint 2: Designing boundary test cases.

Width

Minimum
Identify at least one type of invalid input for a program; test the program with that input and describe what happened; explain what the correct behaviour should be.
Typical
Identify multiple categories of invalid input (wrong type, out of range, missing input, unexpected format); test the program against each; verify that errors are handled appropriately rather than causing crashes or silent failures.
Wider
  • Design a systematic set of invalid input tests that covers all categories of potential user error for a specific program
  • Investigate how professional software uses try/catch or error-handling mechanisms to manage invalid input — compare this to defensive validation at input time

Writing programs with control structures

AC9TDI8P09 n1 · waypoint 1 of 4 · Years 7–8 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write programs in a general-purpose language using branching, iteration and variables to solve problems

Success criteria

  • Writes a program that runs without syntax errors
  • Program uses at least one branching structure and one loop
  • Variables are used to store and manipulate data

Prior knowledge

Students can implement algorithms as visual programs involving control structures, variables and input (AC9TDI6P05). They have programmed in visual/block-based environments but have not yet used a general-purpose text-based language, defined functions, or systematically debugged programs.

Width

Minimum
Write a program that uses at least one branching structure and one loop with variables to solve a given problem
Typical
Write programs using nested control structures (IF inside loops, loops with conditionals) to solve more complex problems; use meaningful variable names and comments
Wider
  • Write a program that receives data from the environment to change behaviour (e.g. reading moisture from a soil sensor to control a watering system)
  • Apply programming to an open-ended student-chosen problem with self-selected context

Hinge

Students who cannot write syntactically correct programs in a text-based language cannot define or call functions (Node 2), read and modify existing code (Node 3), or debug programs (Node 4). Syntax errors block all subsequent production skills in this standard.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Consolidation: more practise steps, short feedback loopsThe transition from visual/block-based to text-based programming requires building syntax fluency. Width is thin — Python syntax doesn't vary across contexts. What helps is more practice: writing more small programs, fixing more syntax errors, building comfort with the text environment.

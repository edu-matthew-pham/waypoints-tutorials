Querying with SELECT, WHERE and JOIN

AC9TDI10P03 n4 · waypoint 4 of 4 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write SQL queries using SELECT, WHERE and JOIN to retrieve and filter data across multiple tables.

Success criteria

  • Correctly writes a SELECT/WHERE query that filters data by a specified condition
  • Correctly writes a JOIN query that combines data from two tables
  • Output matches what the question asks for

Prior knowledge

Waypoint 3: Building and populating the database.

Width

Minimum
Write at least one SQL query that uses SELECT and WHERE to filter rows from a single table, and one query that uses JOIN to combine data from two tables.
Typical
Write queries using SELECT, WHERE, JOIN and GROUP BY/COUNT to retrieve, filter, aggregate and count data across multiple tables; explain what each clause does and why it is needed for the given question.
Wider
  • Write SQL queries to detect data integrity issues (e.g. confirming each user has only reviewed each movie once using GROUP BY and HAVING COUNT)
  • Use SQL to answer a real decision-support question (e.g. identifying which products have no reviews, or which users have the highest activity) and explain how the query logic maps to the question
  • Explore edge cases in JOIN behaviour — what happens with left joins when no match exists, and why this matters for certain queries

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepSQL queries are best learned through varied question types — each question type (filtering, aggregating, joining, detecting duplicates) requires a different clause combination. Students who only practise SELECT/WHERE often struggle when JOIN logic is needed, or don't know when GROUP BY is appropriate.

Writing a user story

AC9TDI6P01 n2 · waypoint 2 of 3 · Years 5–6 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write a user story that identifies who the user is, what they need, and why

Lessons on this site

None yet.

Success criteria

  • Writes a user story that identifies the user, their need, and the reason for the need
  • The user story is consistent with the identified problem

Prior knowledge

Waypoint 1: Identifying a problem from stimulus.

Width

Minimum
Write a user story in standard form: 'As a [user], I need [something] so that [reason]' — linked to an identified problem
Typical
Write one or more user stories that capture the core needs of the user group; use the user stories to clarify what the solution must do versus what would be nice to have
Wider
  • Write user stories for a roadside bushfire or flood risk rating system from the perspectives of two different user groups (e.g. a traveller vs a local resident) — identifying where their needs diverge
  • Discuss user stories that reflect different cultural or accessibility needs — e.g. a user who reads in a language other than English or a user with a visual impairment

Hinge

User stories in N2 are the direct input for N3's criteria co-development — criteria are derived from what the user stories identify as needs. Students who produce vague or missing user stories cannot develop meaningful criteria in N3.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Structured reasoning: a worked chain of reasons, then a write-and-compare (reasoning) checkThe user story format is a reasoning scaffold, not just a template. Students who use it mechanically produce technically compliant stories that miss the 'why' — the reason the user needs the feature is what connects the story to the design criteria. Unpacking the three-part structure explicitly (who / what / why) helps students use it as a thinking tool.

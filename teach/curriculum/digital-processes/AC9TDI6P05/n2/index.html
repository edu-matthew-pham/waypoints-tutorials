Branching and iteration in programs

AC9TDI6P05 n2 · waypoint 2 of 3 · Years 5–6 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can write programs that use branching to respond to different conditions and loops to repeat steps

Lessons on this site

None yet.

Success criteria

  • Program includes at least one branch that produces different behaviour for different inputs
  • Program includes at least one loop with a clear termination condition

Prior knowledge

Waypoint 1: Using variables to store input.

Width

Minimum
Write a program with at least one branch (if/else) that produces different behaviour for different inputs, AND at least one loop that repeats steps a given number of times or until a condition is met
Typical
Write programs that include multi-branch decisions (more than two alternatives), loops controlled by variable values, and combinations of both — e.g. an interactive quiz that checks answers (branching), gives feedback, updates the score (variable), and loops for each question
Wider
  • Write a program that simulates automated ranger tasks — using iteration to repeat a monitoring loop and branching to select an action based on the detected condition (e.g. gate status, animal proximity)
  • Write a program with nested loops — repeating a shape a given number of times while shifting its position on each iteration (Turtle Graphics style)

Hinge

N2's programs must exist and have observable behaviour before N3's verify-and-fix process can proceed — verification requires running a program and comparing actual to expected output. Students who cannot produce a program with branches and loops in N2 have nothing to test in N3.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepStudents who can write a loop or a branch in isolation often struggle to combine them. Programs with a clear, functional purpose — a quiz, a drawing pattern, a simulation — motivate the combination and make the program's behaviour verifiable by inspection.
Integration: a combining task at the wider tierThis node integrates variables (Node 1), branching, and iteration into combined programs. The integration act is coordinating all three — variable value affects branch decision affects loop exit. Programs where the user can trace this chain during execution are the most effective contexts.

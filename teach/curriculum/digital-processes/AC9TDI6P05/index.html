Implement programs with variables

AC9TDI6P05 · Years 5–6 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Descriptor

Implement algorithms as visual programs involving control structures, variables and input

Prior knowledge

Students can implement simple algorithms as visual programs involving control structures and input (AC9TDI4P04). They have written programs with basic sequences, simple branching, and loops in a visual environment. They have not yet used variables to store and reuse values, or combined variables with control structures to respond to user input.

By the end

Students implement algorithms as visual programs that use variables to store input, control structures (branching and iteration) to direct program flow, and produce correct output — verifying and fixing errors.

ACARA elaborations

Examples from ACARA that illustrate this standard. They are examples, not a checklist, and belong to the standard as a whole.

  • writing and editing programs to solve problems using branching, iteration and variables in a visual programming environment, for example writing a program to draw a rotated shape a given number of times using Turtle Graphics
  • writing programs that take input from the user or environment and storing that input in a variable for later use, for example asking the user how many shapes to draw in a circle and using that to calculate the number of iterations and angle to rotate each time
  • writing programs that make decisions involving multiple alternatives, for example an interactive quiz that checks if the answer is correct, gives feedback and updates the score, or gives a final grade based on the score
  • writing programs that repeat multiple steps based on the user's input, for example repeatedly drawing a shape a given number of times, shifting the position between each iteration
  • stating the expected behaviour of a program, running the program to check it is correct and fixing any errors, for example 'when I press the left arrow key, the cat should move left, finding the cat moves right, and fixing it by changing the 10 to -10 to alter the direction'
  • programming digital systems to perform automated tasks, such as closing gates, for example simulating the work of First Nations Australian rangers attempting to lure and capture feral animals

Waypoints

  • 1. Using variables to store inputHingeStudents can write a program that takes input from the user or environment, stores it in a variable, and uses the variable in later steps
  • 2. Branching and iteration in programsHingeStudents can write programs that use branching to respond to different conditions and loops to repeat steps
  • 3. Verifying and fixing programsStudents can state expected program behaviour, test it by running the program, and fix errors when actual behaviour differs from expected

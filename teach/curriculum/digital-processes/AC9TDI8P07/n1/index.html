UX vs UI

AC9TDI8P07 n1 · waypoint 1 of 5 · Years 7–8 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can distinguish user experience from user interface and explain that UX design centres on how users interact with and feel about a system, not just how it looks

Success criteria

  • Correctly identifies UX and UI decisions in a given example
  • Explains that UX includes flow, ease of use, and user satisfaction — not just visual design
  • Does not treat UX and UI as interchangeable

Prior knowledge

Students can design a user interface for a digital system (AC9TDI6P03) and generate, modify, communicate and evaluate design ideas (AC9TDI6P04). They have experience designing interfaces but have not yet considered user experience holistically — including branding, user values, and how design decisions serve user stories.

Width

Minimum
Given examples, identify which design decisions are about user experience (flow, ease of use, satisfaction) and which are about user interface (layout, colour, buttons)
Typical
Analyse an existing digital system — identify UX decisions and UI decisions separately; explain how a good UI can still have poor UX and vice versa
Wider
  • Compare the UX of the same service across different platforms (e.g. mobile app vs website vs voice assistant) — how does the experience change when the interface changes?
  • Limited width — the UX/UI distinction is a single conceptual insight. More examples reinforce but do not meaningfully broaden the understanding.

Hinge

Students who treat UX and UI as interchangeable will produce wireframes that only address layout without considering user flow or satisfaction at Nodes 3 and 5. The UX/UI distinction shapes every design justification in this standard.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepThe UX/UI distinction is a misconception-prone conceptual boundary — students who conflate them will produce wireframes treated as complete UX designs. Seeing the distinction applied across multiple platforms (mobile, web, voice) resolves the misconception more reliably than a single definition.

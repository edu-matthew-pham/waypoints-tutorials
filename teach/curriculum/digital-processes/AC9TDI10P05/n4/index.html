Designing algorithms for real problems

AC9TDI10P05 n4 · waypoint 4 of 4 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can design algorithms involving logical operators to solve a specified real-world problem, including modifying existing algorithms.

Lessons on this site

No lesson is tagged to this waypoint. The standard is generally covered by some courses; see the standard's page for which are the main focus and which only touch it.

Success criteria

  • Algorithm correctly handles the primary case
  • Algorithm handles at least one edge case (e.g. boundary input, conflicting conditions)
  • Algorithm can be traced to verify correct output

Prior knowledge

Waypoint 3: Representing algorithms as flowcharts and pseudocode.

Width

Minimum
Design an algorithm with at least one compound Boolean condition that correctly solves a specified problem, OR modify an existing algorithm to fix or extend it.
Typical
Design or modify an algorithm that uses AND, OR and NOT to solve a problem with multiple conditions — represent it as both flowchart and pseudocode, and verify it handles edge cases correctly.
Wider
  • Design an algorithm to detect whether two shapes intersect, including the edge case where shapes just touch — represent and verify with test cases
  • Design an algorithm with Boolean conditions for a decision-making context (e.g. eligibility checking, sensor-triggered automation) and evaluate it against a range of scenarios
  • Extend an existing algorithm with new requirements expressed as additional Boolean conditions — explain how the extension changes the algorithm's behaviour

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Integration: a combining task at the wider tierNodes 1–3 address Boolean operators, compound conditions and representation separately. The design node requires students to coordinate all three — understanding what condition is needed, expressing it correctly with Boolean operators, and representing it unambiguously. Students who can do each part individually often struggle to design from scratch.

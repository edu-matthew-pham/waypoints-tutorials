What structured data is

AC9TDI8P03 n1 · waypoint 1 of 3 · Years 7–8 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can explain that structured data represents objects or events as records with defined attributes, and identify what attributes are relevant for a given purpose

Lessons on this site

No lesson is tagged to this waypoint. The standard is generally covered by some courses; see the standard's page for which are the main focus and which only touch it.

Success criteria

  • Identifies at least three relevant attributes for a given object or event
  • Explains why each attribute is relevant to the purpose

Prior knowledge

This is the first standard in the Modelling Data sub-strand (begins at 7-8). Students have used spreadsheets to store and organise data (AC9TDI8P01) but have not yet modelled objects and events as structured data with defined attributes, nor queried data using filtering, sorting or SQL.

Width

Minimum
Given an object or event, name at least three attributes that describe it; explain why the chosen attributes are relevant to the task
Typical
Model objects and events from a real scenario (e.g. canteen products with name, price, quantity, nutritional value); choose appropriate data formats for each attribute (text, number, date)
Wider
  • Design a database schema for a real-world context and justify why each attribute was included and what was excluded
  • Compare how the same event (e.g. a sports match) would be modelled differently for different purposes (scheduling vs statistics vs commentary)

Hinge

Students who cannot identify relevant attributes for a given purpose will create tables at Node 2 with missing, irrelevant or incorrectly formatted fields. Poorly structured tables cannot be queried meaningfully at Node 3 — the data model shapes every query.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Structured reasoning: a worked chain of reasons, then a write-and-compare (reasoning) checkSelecting relevant attributes requires students to reason from purpose: what question are we answering? → what information does the query need? → which attributes capture that information? Students who list attributes without connecting them to purpose create tables that cannot answer the intended question when queried at Node 3.

Comparison operators as branching conditions

AC9TDI4P02 n2 · waypoint 2 of 4 · Years 3–4 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can describe a branch in an algorithm using a comparison operator (e.g. if UV index > 3, if score = 10) and explain what each path does

Success criteria

  • Correctly traces both branches of an algorithm with a comparison condition
  • Names the comparison operator (greater than, equal to, etc.) used in the branch

Prior knowledge

Waypoint 1: Sequencing as ordered steps.

Width

Minimum
Given an algorithm with one branch using a comparison (e.g. if temperature is above 25°C), trace both paths and describe what happens in each case
Typical
Describe algorithms with multiple branches using comparison operators (greater than, less than, equal to) involving numbers and text; trace the correct path for different input values
Wider
  • Describe algorithms that branch on comparisons involving culturally specific conditions — for example, IF a certain animal is found in a ranger survey THEN a specific protocol applies; discuss how the comparison drives the decision
  • Explore algorithms involving combined conditions (e.g. IF UV index > 3 AND it is a school day) — describe what the combined comparison checks for

Hinge

Comparison operators are directly prerequisite for implementing branching in AC9TDI4P04 — students who cannot identify the condition and trace both paths cannot write a working conditional program.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepComparison operators abstract quickly from the concrete case. Students who only see one type of comparison (e.g. 'greater than' with temperature) may not recognise that text comparisons, equal-to checks, and multi-condition branches follow the same logic. Multiple contexts build the generalised pattern.
Structured reasoning: a worked chain of reasons, then a write-and-compare (reasoning) checkTracing both branches of a conditional requires holding two cases simultaneously. Students benefit from explicit scaffolding: 'what happens if the condition is true? what happens if it is false?' before attempting to write their own branches.

Establishing design criteria

AC9TDI10P04 n4 · waypoint 4 of 4 · Years 9–10 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can establish design criteria derived from user stories and problem definition that will guide evaluation of solutions.

Success criteria

  • At least two design criteria are written that are checkable against a solution
  • Criteria are derived from user stories, not generated independently

Prior knowledge

Waypoint 3: Defining the problem with precision and scope.

Width

Minimum
Write at least two design criteria derived from user stories; criteria must be assessable (checkable against a solution).
Typical
Establish a set of design criteria from user stories and problem definition; ensure criteria are specific and assessable; include both functional criteria (what the system does) and non-functional criteria (how it performs or what constraints apply).
Wider
  • Develop design criteria that explicitly account for diverse user needs — including accessibility criteria for users with different abilities
  • Compare functional and non-functional design criteria for a system and explain why non-functional criteria (e.g. performance, privacy, accessibility) are as important as functional ones

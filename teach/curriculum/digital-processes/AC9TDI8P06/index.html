Trace algorithms for errors

AC9TDI8P06 · Years 7–8 Digital Technologies (processes) · Processes and production skills

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Descriptor

Trace algorithms to predict output for a given input and to identify errors

Prior knowledge

Students can design algorithms with nested control structures and represent them in flowcharts and pseudocode (AC9TDI8P05). They can follow simple algorithms but have not yet systematically traced algorithms using desk checks, specified test cases with expected outputs, or identified errors through tracing.

By the end

Students trace algorithms step by step to predict output for given inputs, specify test cases with expected and actual outputs, and identify and explain errors found through systematic tracing.

ACARA elaborations

Examples from ACARA that illustrate this standard. They are examples, not a checklist, and belong to the standard as a whole.

  • following an algorithm precisely to confirm it produces the expected output for the given input, for example desk check with a table of input, variables and output
  • specifying test cases and comparing the expected and actual output to determine the correctness of an algorithm, for example a test case of the change-calculating algorithm could have input $1.45 and expected output 1 x $1, 2 x 20c and 1 x 5c coins
  • following instructions for making woven baskets or nets by hand, as done by First Nations Australians, and making predictions of how the instructions would need to be modified to enable the item to be produced through automated manufacturing processes

Covered in these courses

Main focus: every Code course

Every Code lesson starts by asking students to predict what a program will do.

This is general coverage, not a lesson tagged to each waypoint. A course that only touches a standard meets it in passing; it may not be the course's main focus, and a teacher could extend it to cover the standard more fully.

Waypoints

  • 1. Tracing step by stepHingeStudents can trace an algorithm precisely, step by step, tracking variable values to predict the output for a given input
  • 2. Specifying test casesStudents can specify test cases by choosing inputs and stating expected outputs before tracing
  • 3. Identifying and explaining errorsStudents can identify errors in an algorithm by comparing expected and actual outputs, and explain what caused the error

Identifying a user and their problem

AC9TDI2P01 n1 · waypoint 1 of 3 · Years 1–2 Digital Technologies (processes) · Processes and production skills · Hinge

Draft, from Waypoints Kit v0.2. Generated from Kit's node data and not yet reviewed by a specialist in Digital Technologies (processes): treat it as a starting suggestion and check it before use.

Checkpoint

Students can identify a known user and describe a simple, specific problem that user has

Success criteria

  • Names a specific user (not 'everyone' or 'people')
  • Describes the problem from the user's perspective — what they can't do or find difficult, not what solution they want

Prior knowledge

Students have not yet formally investigated problems. They have encountered digital systems in familiar contexts and can recognise when a digital system helps them do something. They have not yet structured a problem investigation — identifying a user, a problem, and how a digital system could address it.

Width

Minimum
Name a known user (themselves, a classmate, family member) and describe one specific problem they experience that a digital system might help solve
Typical
Identify multiple known users across familiar contexts (home, school, community) and describe a specific, observable problem for each; confirm the problem is real by asking the user or observing directly
Wider
  • Investigate how digital translation tools could address communication problems for First Nations Australians — identify a specific user and language communication need
  • Explore how a familiar community problem (e.g. knowing if the school library book you want is available) could be described as a problem for a known user

Hinge

Without a named user and a described problem, Node 2's investigation has no subject — students cannot establish what a problem involves if no user or problem has been identified.

Response modes

Where extra effort goes at this waypoint (width), not what kind of lesson it is.

Context breadth: more contexts in the vary or modify stepStudents at this level often describe problems too broadly ('everyone wants to play games') or describe solutions before problems ('we need an app'). Encountering a range of specific, distinct user contexts — different people with different problems — helps students develop the habit of grounding problems in a real, named user before jumping to solutions.

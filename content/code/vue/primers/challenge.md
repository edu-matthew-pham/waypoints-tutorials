## The idea in plain words

Students build a to-do app from everything in the course, in three milestones with fading support: most of the code, then an outline in comments, then only the goals. Each milestone has its own starting point (**Reset to this task's start**), so a student who falls behind can still finish. Then they add a feature of their own. The optional lesson builds the same kind of app in Vue, Preact and Svelte.

## Why programmers use it

The to-do list is the classic first app for every framework, because it needs data, events, a worked-out value and a component, and nothing else.

## An everyday picture, and where it breaks

Building flat-pack furniture with the instructions thinning out: step-by-step for the first drawer, a diagram for the second, just a photo for the third. It breaks if a student skips the first two: the milestones are the instructions.

## Try it yourself (5 minutes)

Build milestone 1 yourself before the lesson, then open the finished app and tick a task: say which Vue piece makes each thing happen.

## Questions students ask

- **Why use a for loop for the count?** It uses what you know. `filter` is a shorter way, for later.
- **Will it remember my tasks?** Not yet: refresh the page and they are gone. Saving them (localStorage) is a stretch.
- **Is this how real apps are made?** Yes, with a build tool and one file per component; the ideas are the same.

## How it connects

The optional lesson compares Vue with Preact (React's small cousin) and Svelte, so students see which ideas belong to all frameworks.

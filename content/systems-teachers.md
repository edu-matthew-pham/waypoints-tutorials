## What is here

No coding needed. Short lessons on how a computer stores and moves data and how it is kept safe, for Years 5 to 10. Each lesson is a board to try (a pretend network, a pixel grid, a processor, a terminal), a worked example and a few checks. They suit introducing an idea or revising it, and they sit beside your own teaching rather than instead of it.

The subject follows the Digital Technologies **Knowledge and understanding** strand, plus the security and privacy standards in Processes. The [curriculum map](../systems/map/) shows which descriptor each lesson covers.

## Which course do you start with?

- **New to the ideas, or Years 5–6:** [Starting out](../systems/starting/): letters as codes, on and off, counting, the parts inside, and how computers join up.
- **Data:** [Data representation](../systems/data/) (text, colour, images, sound as numbers, then binary), then [Making data smaller](../systems/compression/) and [How a web page is made](../systems/web/).
- **Networks and security:** [Networks](../systems/networks/) (follow a packet) and [Cyber safety and privacy](../systems/cyber/) (passwords, phishing, privacy) are the two foundations. [Security and privacy](../systems/security/) and [Capture the flag](../systems/ctf/) come after.
- **Hardware and logic:** [Inside a computer](../systems/hardware/), then [From gates to a processor](../systems/logic/).
- **The command line:** [The command line](../systems/shell/), then [System admin on a Raspberry Pi](../systems/sysadmin/) or [Security lab](../systems/seclab/) (Years 9–10).

## What you need

Almost nothing: a browser. The command line courses use a pretend Linux computer in the browser.

Two courses have optional real-hardware versions, set out in each lesson's teacher notes:

- **System admin on a Raspberry Pi:** a Pi 4 or 5.
- **Security lab:** a Pi running Kali and a target on an isolated switch with no internet. This is **audit and defence only**, and the real-lab version needs your sign-off. The pretend version needs nothing.

## Security teaching

The security courses are defensive and conceptual: how things fail, how to spot it and how to fix it. There is no attack or exploit practice. The capture-the-flag finales use made-up systems and flag answers, with the flags in each course's teacher notes.

## For you

Each course page links a **Teacher guide**: a guide for each lesson (goals, timing, what to say, misconceptions, an exit ticket), a deck, a worksheet and printable cheat sheets. Courses also have **project briefs**, printable task sheets with success criteria taken from the curriculum descriptors.

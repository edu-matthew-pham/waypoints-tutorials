How you learn best: cards

One screen for each strategy, to look up when you need one, in any subject. Each card says when to use it, what to do, one thing to watch for, and what it looks like in different subjects. Pick the one that fits the kind of stuck you're in.

Before a task

What is it asking?

Use it when you're not sure what to do or hand in. Many mistakes start with answering a different question.

  1. Read the task once all the way through.
  2. Say in one line what you have to find, make or hand in.
  3. Underline the words that tell you how: 'explain', 'compare', 'show working', 'by Friday'.
  4. Check: if you did exactly that, would you be finished?

Watch for: A task can look like one you've done before and ask for something different.

Maths
Which number is the answer meant to be? Check the units it asks for.
Science
What is the experiment trying to find out? Say it as a question.
English
What kind of text, for whom, and how long?
Code
What should the program do? Say what goes in and what comes out.

Lesson: Your strategies

Make a plan

Use it when you understand the task but don't know where to start. A plan can be one line.

  1. Write your first step, only the first.
  2. Break a big task into three or four parts.
  3. Stuck on the first step? Try a smaller or simpler version first.
  4. Decide how you'll know each part is done.

Watch for: A plan isn't a promise. Change it when you learn something.

Maths
Try the same question with smaller, easier numbers.
Science
List the steps of the method before you start.
English
Jot the three points of your paragraph or essay first.
Code
Get one small piece working, then add the next.

Lesson: Your strategies

During a task

Predict first

Use it before you work something out or run it. A guess gives you something to check against.

  1. Before you work it out, guess the rough answer or what will happen.
  2. Write the guess down so you can't change it.
  3. Work it out or try it.
  4. Compare: if it's very different, find out why.

Watch for: A wrong prediction isn't a failure. It's the most useful kind, because it shows what you didn't expect.

Maths
Estimate first: about how big should the answer be?
Science
Predict the result before the experiment.
English
Predict what the next paragraph will say, then read it.
Code
Say what the program will do before you run it.

Lesson: Your strategies

Check your confidence

Use it when something feels easy or familiar. Feeling sure isn't the same as being right.

  1. Ask: how sure am I, out of 10?
  2. Ask: how could I check without my notes or the answers?
  3. Do the check: put the answer back, try a question, or explain it.
  4. If the check and the feeling disagree, trust the check.

Watch for: Rereading makes things look familiar, which feels like knowing.

Maths
Put your answer back into the question. Does it work?
Science
Does the answer make sense? A 400 kg apple doesn't.
English
Cover the text. Can you say its main idea in one sentence?
Code
Run it with an input where you know the right output.

Lesson: When easy fools you

Explain it to yourself

Use it when you can follow something but aren't sure why it works. Explaining shows the gaps.

  1. Say each step out loud, or write it in your own words.
  2. For each step, say why, not just what.
  3. Mark the step you can't explain yet.
  4. Go back to that step only.

Watch for: Copying an explanation isn't the same as giving one. Close the book first.

Maths
Say why each line of working follows from the one before.
Science
Explain the result using the model or idea, not just what happened.
English
Explain why the writer chose that word or that order.
Code
Say what each line does, or write it as a comment.

Lesson: Your strategies

When you're stuck

Use it when you've been stuck for a while. First work out what kind of stuck it is.

  1. Pause. Take a breath: frustration makes people guess.
  2. Ask: is it the task (what is it asking?), the start (make a plan), or an answer that doesn't fit (check it)?
  3. Try the strategy that fits, for a few minutes.
  4. Still stuck? Try another, or ask someone what kind of stuck they think it is.

Watch for: Reading the same thing again and again rarely helps. Change what you're doing.

Maths
Try a smaller example, or draw it.
Science
Go back to the question the experiment was asking.
English
Talk it through out loud before you write.
Code
Read the error message, then test one small part.

Lesson: Your strategies

After a task

Look back

Use it when you finish something or get it back marked. Next time starts here.

  1. Ask: did it work? Did I do what the task asked?
  2. Find one thing that went well and one to change.
  3. Ask: is this a mistake I've made before?
  4. Write the one change somewhere you'll see it next time.

Watch for: Looking back isn't about the mark. It's about what you'll do differently.

Maths
Which kind of question lost marks? Practise that kind.
Science
Did the conclusion use the data?
English
Reread it as a reader: where did it lose you?
Code
Could you write it again without looking? What would you change?

Lesson: What's going on in your head?

In maths

Estimate first

Before you work it out: round the numbers and guess roughly how big the answer should be, so a wrong answer stands out.

  1. Round each number to something easy.
  2. Work out the rough answer in your head.
  3. Write the estimate down, then do the real working.
  4. Compare: if they're far apart, look for the slip.

Watch for: An estimate isn't the answer. Use it to check, then do the real working.

Number
19.8 × 4.1 is about 20 × 4 = 80.
Measurement
A classroom floor is tens of square metres, not thousands.
Statistics
The mean must sit between the smallest and biggest values.

Lesson: Your strategies

Is it reasonable?

During and after: read your answer as a real thing. Does the size, sign and unit make sense?

  1. Say the answer in words, with its unit: '400 kilograms'.
  2. Ask: is it about the right size?
  3. Check the sign: can it be negative here?
  4. Check the unit: is it the one the question asked for?

Watch for: A neat answer can still be wrong. A messy one can still be right.

Number
A discount can't make a price go up.
Measurement
Area is in square units; volume in cubic units.
Probability
A probability is between 0 and 1.

Lesson: Your strategies

Try a simpler case

When you don't know where to start: shrink the problem until you can do it, then grow it back.

  1. Swap in small, friendly numbers.
  2. Solve that version, and notice the steps you used.
  3. Use the same steps on the real numbers.
  4. Or draw it: a sketch, a number line or a table.

Watch for: Check the simpler case really is the same problem with smaller numbers.

Algebra
Try x = 1, 2 and 3 to see the pattern.
Geometry
Sketch it, then label what you know.
Number
Not sure whether to multiply or divide? Try it with 10 and 2.

Lesson: Your strategies

Check by working backwards

After: put your answer back into the question and see if it works.

  1. Take your answer.
  2. Put it back into the original question or equation.
  3. Work it through.
  4. Does it give what the question said? If not, find the slip.

Watch for: Check against the original question, not your own working: the slip may be in the working.

Algebra
Substitute x back into the equation.
Number
Check a division by multiplying.
Percentages
Add the increase back on: does it reach the new price?

In science

Predict, then compare with the data

Before an experiment: write what you expect and why. After: compare it with what happened.

  1. Write a prediction with a reason: 'I think… because…'.
  2. Do the experiment and record what happened.
  3. Compare: did the data match?
  4. If not, ask what that tells you. It's often the most interesting part.

Watch for: Don't change the prediction afterwards. A wrong prediction is a result too.

Practical
Write the prediction before you touch the equipment.
Simulation
Predict before you press Run or move the slider.
Written answer
Say whether the evidence supports your prediction, and how.

Lesson: Your strategies

Is the test fair?

Before and during: change one thing, measure one thing, and keep everything else the same.

  1. Name the one thing you'll change.
  2. Name the one thing you'll measure.
  3. List what you'll keep the same.
  4. Partway through, check: has anything else changed by accident?

Watch for: Small things sneak in: a different cup, a warmer room, a later time.

Practical
Use the same equipment and amounts each time.
Planning
Write the changed, measured and kept-same lists before you start.
Written answer
Say what you kept the same, and why it mattered.

Lesson: Your strategies

Check the data

After collecting results: look for anything odd before you draw a conclusion.

  1. Look for a result that doesn't fit the pattern.
  2. Check its units and how it was measured.
  3. Repeat it if you can.
  4. Say how sure you are, and why.

Watch for: Don't quietly delete an odd result. Say what you did about it.

Practical
Three repeats show whether a result is a one-off.
Graphs
A point far from the line is worth a second look.
Written answer
Mention the odd result and what you think caused it.

Lesson: Your strategies

Explain it with the model

When explaining a result: use the science idea (particles, forces, energy, cells), not just what you saw.

  1. Say what happened.
  2. Name the model or idea that explains it.
  3. Link them: 'This happened because…' using the model.
  4. Check: could a classmate follow the link?

Watch for: Describing what happened isn't explaining why it happened.

Chemistry
Use particles: what are they doing?
Physics
Name the forces or the energy transfers.
Biology
Say what the cells, organs or organisms are doing.

In English

Purpose and audience first

Before writing: say what the text is for and who will read it. Every later choice depends on it.

  1. Say the purpose: to persuade, explain, entertain, analyse.
  2. Say who will read it and what they already know.
  3. Pick the form: essay, report, story, speech.
  4. Keep the purpose and audience at the top of your page.

Watch for: Writing well for the wrong audience still misses.

Persuasive
Who do you need to convince, and what will they object to?
Imaginative
What do you want the reader to feel?
Analytical
What's your one main point about the text?

Lesson: Your strategies

Plan your points

Before drafting: jot your main points in order, so each paragraph has one job.

  1. Write your main idea in one sentence.
  2. List two to four points that support it.
  3. Put them in the best order.
  4. Give each paragraph one point.

Watch for: A plan can change as you write. Update it, don't abandon it.

Persuasive
Strongest point first or last, not in the middle.
Imaginative
Beginning, problem, turning point, ending.
Analytical
One point per paragraph: claim, evidence, explanation.

Lesson: Your strategies

Reread aloud

During and after: read your writing out loud, as a reader would hear it. Your ears catch what your eyes skip.

  1. Read it out loud, or quietly under your breath.
  2. Mark anywhere you stumble or run out of breath.
  3. Mark anywhere you lose track of what 'it' or 'this' means.
  4. Fix the marked spots first.

Watch for: Reading it in your head, you read what you meant, not what you wrote.

Persuasive
Does each paragraph push the same way?
Imaginative
Do the sentences vary in length and rhythm?
Analytical
Does every quote get explained?

Lesson: Your strategies

Check each paragraph's job

After drafting: check that each paragraph does one job and links to the next.

  1. Read just the first sentence of each paragraph.
  2. Ask: do these alone tell the main points, in order?
  3. In each paragraph, check every sentence belongs to its point.
  4. Check the links between paragraphs: does each lead into the next?

Watch for: A new point in the conclusion is a sign it belongs earlier.

Persuasive
Each paragraph should give one reason.
Analytical
Claim, evidence, explanation in each body paragraph.
Report
Does each heading match what's under it?

In Code

Say what it should do

Before you code: say what the program should do, with a few examples, so you know what 'working' means.

  1. Write in one line what the program should do.
  2. Write two or three examples: this input should give this output.
  3. Include one awkward case: zero, an empty answer, a very big number.
  4. Keep the examples to test with later.

Watch for: If you can't say what it should do, coding it won't help yet.

Python
Write the examples as comments at the top.
MakeCode
Say what the micro:bit should show when each button is pressed.
Web
Sketch what the page should look like first.

Lesson: Your strategies

Test a small piece

During: add a little, run it, check it. Small steps mean a problem is always in the last thing you changed.

  1. Add one small piece: a line, a block, a tag.
  2. Predict what it will do, then run it.
  3. Check it against your examples.
  4. Only then add the next piece.

Watch for: Writing a lot before running anything makes bugs hard to find.

Python
Run after every few lines. Use print to see a value.
MakeCode
Watch the simulator after each block you add.
Web
Look at the preview after each tag or rule.

Lesson: Your strategies

Read the error

When it breaks: the error message is a clue, not a telling-off. It usually says where to look.

  1. Find the line number in the message.
  2. Read the line, and the line above it.
  3. Say in your own words what the message means.
  4. Change one thing, then run it again.

Watch for: The real mistake is often on the line before the one the error names, such as a missing bracket.

Python
The playground puts the line and a hint first: start there.
MakeCode
Look for red or grey blocks, or a block that isn't connected.
Web
Nothing appears? Check the tag before it is closed.

Lesson: Your strategies

Trace it

When it runs but does the wrong thing: be the computer. Step through it by hand and track every value.

  1. Pick a small input.
  2. Go line by line, writing down each variable's value.
  3. Stop at the first line where a value isn't what you expected.
  4. That's where to fix it.

Watch for: Tracing what you meant to write instead of what you wrote. Read the actual code.

Python
Use a table: one column per variable, one row per line run.
MakeCode
Follow each block in order, especially loops and ifs.
Web
Find the rule that applies to the element, then check which one wins.
